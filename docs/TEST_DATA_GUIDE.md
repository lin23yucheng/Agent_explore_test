# 测试数据使用说明

本文档用于准备、执行和清理 VLA 数据任务平台的测试数据。测试执行前应结合本文件、当前有效用例 CSV、页面实际行为和已有自动化脚本共同判断。

## 测试账号

基准管理员账号：

- 用户名：`admin`
- 密码：`123456`
- 角色：管理员
- 权限：所有菜单权限

如需验证不同权限，应在“用户管理”中新建测试用户，新增时在角色下拉框选择对应角色，初始密码统一为 `123456`。

## 角色与菜单权限

| 角色 | 权限 |
| --- | --- |
| 管理员 | 所有权限 |
| 算法工程师 | 工作台、任务管理、数据转换、数据可视化 |
| 采集工程师 | 工作台、我的采集 |
| 标注工程师 | 工作台、我的标注 |
| 质检工程师 | 工作台、我的质检 |

## 基础配置数据

以下数据可以在对应管理页面自行新增。除基准管理员和系统已有基准数据外，测试创建的数据统一使用 `AI` 开头，建议追加运行标识和 CASE-ID，例如 `AI_RUN123_CASE000001_任务1`，避免与其他执行批次冲突。

### 机器人构型

当前支持三种类型：

- 天机
- 夹爪
- 摇操

任务创建时必须选择机器人构型。后续“我的采集”上传的数据必须与任务选择的机器人构型匹配。当前执行不要求重新上传大体积采集数据，优先复用系统中已有、可用且与构型匹配的数据。

### 标签

标签在“标签管理”中自行新增。任务创建时可以多选标签；后续“我的标注”可以直接使用任务创建时绑定的标签。

### 数据分类

数据分类在“数据分类管理”中自行新增。任务创建时需要选择对应分类；数据转换完成后，生成的数据应在该分类下通过“数据可视化”查看。

## 业务流程

完整业务链路如下：

1. 配置用户、角色、标签、机器人构型和数据分类。
2. 在“任务管理”新建任务，填写用例要求的必填字段，选择机器人构型、标签和数据分类。
3. 在“我的采集”上传与机器人构型匹配的数据，完成采集。当前优先使用页面已有数据，不主动上传大体积文件。
4. 在“我的标注”进行视频标注并提交标注。
5. 在“我的质检”检查并修改标注，完成质检。
6. 在“数据转换”选择已完成质检的任务进行转换。
7. 转换成功后，在“数据可视化”对应数据分类下查看生成数据。

## 执行范围限制

当前用例尚未覆盖以下模块的独立功能：

- 工作台
- 我的采集
- 我的标注
- 我的质检
- 数据转换
- 数据可视化

如果当前用例依赖上述后续流程，但没有现成可靠的数据或自动化脚本，暂不强行执行，结果标记为“环境/数据前置阻塞”或“需求不明确”，并记录具体缺少的前置条件。可以执行不改变数据的页面查询、列表查看等轻量操作。

## 暂不执行的场景

当用例要求系统处于当前环境无法安全构造的状态时，暂不执行并记录原因。例如“任务总数为 0”，但系统已有任务且这些任务不能删除，不应为了满足用例破坏基准数据。

## 数据清理规则

- 测试创建的用户、任务、标签、数据分类等数据都必须使用 `AI` 前缀。
- 每条测试创建数据时记录其名称、CASE-ID 和运行标识。
- 用例成功或失败都必须清理自己创建的数据。
- 清理前先解除引用关系，例如任务关联的标签、分类或其他对象。
- 清理后再次查询确认数据已删除。
- 如果系统明确拦截删除或数据属于系统基准数据，可以保留，但必须在结果中标记 `retained-by-design` 并说明原因。
- 不删除 `admin` 基准账号和系统原有基准数据。

## 执行判定原则

用例中的新增字段、必填字段和校验规则以当前 CSV 中的最终描述为准。实际执行时应读取控件最终值，并验证提交后的列表、详情或最终业务状态；不能只验证弹窗关闭或按钮点击成功。
